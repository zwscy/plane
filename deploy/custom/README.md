# 自定义字段版本：本地构建与运行

源码位于仓库根目录。Web、管理后台和 API 使用本仓库源码构建；Space、Live、代理等辅助服务沿用固定的官方 CE `v1.4.3` 镜像。构建脚本使用仓库指定的 pnpm 版本和锁文件。

管理后台镜像默认标记为 `plane-custom/admin:local`，可通过 `PLANE_ADMIN_IMAGE` 覆盖。打包使用官方 CE `v1.4.3` 的 nginx 运行环境，覆盖 `/god-mode/` 的入口与新静态文件，同时保留旧哈希资源，便于已打开的页面在升级期间继续加载；构建时可通过 `ADMIN_RUNTIME_IMAGE` 指定已加载的固定版本镜像。

功能范围和已运行的检查见 [本地验证记录](VERIFICATION.md)。

## 配置和启动

在仓库根目录创建 `.local/runtime.env`，参考本目录的 `runtime.env.example`，为数据库、消息队列、对象存储和应用密钥填写独立随机值。该文件仅限本机，设置权限 `600`，不要提交。

```bash
./deploy/custom/build-local.sh
./deploy/custom/manage.sh up -d plane-db plane-redis plane-mq plane-minio
./deploy/custom/manage.sh run --rm migrator
./deploy/custom/manage.sh up -d
./deploy/custom/manage.sh ps -a
```

默认入口为 http://localhost:8090，仅监听本机。配置副本测试时，可将 `LISTEN_HTTP_PORT` 改为 `8091`，并同时将 `WEB_URL` 和 `CORS_ALLOWED_ORIGINS` 改为 `http://127.0.0.1:8091`。

停止使用 `./deploy/custom/manage.sh stop`。数据保存在 `plane-custom_` 命名卷，停止容器不会删除数据。不要对有用的数据卷运行 `down -v`。

## 字段管理

项目管理员进入“项目设置 → 自定义字段”。新增字段时选择类型，维护选项并调整顺序；成员在任务创建和详情中填写值，在列表或表格的“显示”菜单切换可见性。

“签收顺序”可选择整数，“预计工时”可选择小数。单值字段支持排序，多值字段不支持排序。状态、周期、模块等新增引用字段独立保存，不会改变任务原有业务关系。已有值时锁定字段类型；清空所有任务中的值后可改类型。停用和逻辑删除字段保留历史数据。

## 项目条件筛选

项目工具栏的筛选按钮打开条件面板，按“字段 → 条件 → 值”设置，并选择“满足全部条件”或“满足任一条件”。字段列表包含内置字段和本项目启用的自定义字段；自定义字段名称、图标与表头一致，隐藏列仍可筛选。数字按数值比较，支持小数、零和负数；“为空”包含未设置、空文本和空列表，零和“否”属于已填写。

编辑条件后点击“应用筛选”生效；取消编辑保留当前筛选。应用前校验条件及服务端字段可用性；失败时保留编辑内容。筛选沿用个人配置保存，刷新后保留，不修改项目默认显示配置。原有复杂嵌套条件会保留并提示，只有明确清空后才替换。跨项目的工作区筛选继续使用原筛选入口。

筛选按每条任务自身的值匹配，不继承父任务字段。展开子任务仍保留原有树形展示行为；展开内容不代表每个子任务均命中当前条件。

## 项目默认显示配置

在项目工作项的“显示”菜单或表格右侧“列设置”面板，管理员可将当前显示字段、列顺序、任务排序和子任务展示方式保存为项目默认。成员首次进入时跟随默认，自行调整这些设置后改用个人配置；点击“恢复项目默认”可重新跟随。管理员更新默认不会覆盖成员的个人配置，跟随者刷新或重新进入项目后采用新的默认。

本次升级先备份旧配置，再由 `0128_project_display_defaults_follow_all` 一次性将所有已有成员的跟随标志设为启用（包括软删除的历史配置行）。已设置的项目默认保持不变；尚未设置的项目默认，应在执行迁移前以确认过的当前管理员显示配置初始化。迁移只修改跟随标志，原个人显示 JSON、筛选条件、偏好和时间戳均保留。筛选条件、布局和分组始终按个人保存，恢复项目默认不会清除这些设置。

初始化只发生在这次迁移中。之后成员自行调整显示设置仍可保存为个人配置，普通请求、后续启动和管理员更新项目默认均不会再次统一重置跟随标志。`0127` 保留原有迁移行为，`0128` 负责本次已确认的历史数据策略；仅回退迁移不会恢复旧跟随状态，需要恢复升级前备份。

## 备份、升级和回退

先备份当前数据库、附件和部署配置，再将数据恢复到独立卷中运行迁移及验证。备份和密钥必须保存在 Git 目录之外或被忽略的本机目录，不能提交。

本机旧环境位于 `/Users/work/Documents/本电脑/plane-local`。切换到改造版前停止旧环境；旧卷和备份继续保留。需要回退时，先停止本版本，再在旧目录运行 `./manage.sh up -d`，恢复原来的本机端口入口。旧版本不能直接连接已经执行新版迁移的数据库。

本地体验可以使用功能分支。dev2 部署须等待用户完整测试确认，并使用已验证、已合入且已推送到 `master` 的 Git 提交和相应架构镜像；先更新 `origin/master` 并按 [dev2 部署说明](../dev2/README.md) 构建，重新备份、迁移并验证，不直接搬运本机开发环境。GitHub 推送不会自动部署 dev2。
